## 2026-07-27T11:26:08.002Z — The `residual` public signal is negative 44.3% of the time and reads as **2.19e76** — MEASURED

A trap for whoever integrates this, found by checking a claim instead of asserting it.

The circuit exposes `residual` and `tolerance` as public outputs so a verifier can see the slack
actually used rather than trusting that a bound existed. But `residual` is a **field element**, and
the field has no sign. Measured over the same 2400-position envelope: **1062 / 2400 (44.3%) of
honest positions have `R < 0`.**

Proven end to end on `{M: 0.00025, q: 0.001, P0: 0.5, s: +1, mmr: 0.001}` — proof generated, verified
`true`:

```
true residual R              -250000000000000
publicSignals[0] (residual)  21888242871839275222246405745257275088548364400416034343698203936575808495617
publicSignals[1] (tolerance) 1001000000000000
naive Number() reading       2.189e+76
```

So the obvious on-chain sanity check — `require(2 * residual <= tolerance)` — **fails on 44.3% of
honest proofs**, because 2.19e76 is not ≤ 1.001e15. It would reject valid proofs almost half the
time, and the failure would look like a broken circuit rather than a broken reading.

A consumer must map the signal back to a signed value first: if `residual > p/2`, the true value is
`residual − p`. Noted in INTEGRATION.md §6. The circuit itself is fine — it constrains
`2R + tol ∈ [0, 2·tol]` precisely because the field has no order — this is purely a hazard for code
*reading* the exposed signal.

### The integration hazard: a malformed proof point burns the entire gas limit

A wrong public *signal* rejects cheaply (235k). A wrong proof *point* does not. `pi_a[0] + 1` is a
valid field element but is not on the curve, so pairing precompile `0x08` fails — and a failed
precompile consumes every unit of gas forwarded to it. Measured across three limits:

| gas limit given | gas consumed | share of limit |
|---|---|---|
| 1,000,000 | 985,282 | 98.5% |
| 2,000,000 | 1,969,657 | 98.5% |
| 5,000,000 | 4,922,782 | 98.5% |

It is not a large constant; **it is whatever you hand it.** A contract that calls `verifyProof` with
all remaining gas and expects to emit an event or revert with a reason on failure will discover it has
nothing left to do it with. **Cap the gas on the `verifyProof` call.** This is measured behaviour of
the generated verifier, and an integrator following the snarkjs README would not learn it.

## 2026-07-27T11:21:01.693Z — The circuit accepts **any** liquidation price you pay the right margin for — MEASURED

This is the most important limitation in the whole track and it is not a bug.

Every input is public and every input is free. So an adversary picks whatever `P_liq` they like, then
solves the identity for the `M` that makes it true. Measured, on the reference position
`{q: 0.5, P0: 100000, s: +1, mmr: 0.005}`:

| claimed `P_liq` | margin required | in range? | circuit |
|---|---|---|---|
| 60,000 | M = 20,150 | yes | **ACCEPT** |
| 1 | M = 49,999.5025 | yes | **ACCEPT** |
| 999,999,999 | M = −497,449,999.5025 | **negative** | REJECT |

Residual is exactly zero in all three cases — the identity genuinely holds. The third fails only
because a real position cannot have negative posted margin, and `Num2Bits(80)` catches it.

**So a verified proof does not say "this is your liquidation price."** It says "these six numbers are
mutually consistent under the liquidation identity." Binding them to an actual customer position
requires a signature over the request, or on-chain state, and that binding is **outside this
artifact**. Any integration that verifies the proof and skips that step has verified arithmetic about
numbers the prover chose freely.

**A correction, recorded because the discipline demands it.** The first draft of this test asserted
REJECT and passed — but for the wrong reason. The required margin was being truncated by BigInt
division, and the leftover remainder broke the residual bound; the 80-bit range check, which the test
claimed was doing the work, never fired at all. The test agreed with its author rather than with the
circuit. Fixed to derive its expectation from the inputs instead of asserting one. A check that
passes for a reason you did not intend is not a check.

## 2026-07-27T11:18:32.205Z — 53 negative cases, all behave as expected; a wrong `P_liq` off by **one 1e-9 step** is rejected — MEASURED

`scripts/negative.js`. **53 cases, 53 as expected, 0 unexpected.** The suite deliberately spans two
different failure surfaces, because they are different claims:

- **Witness-generation failure** — the R1CS is unsatisfiable, so no honest prover can build a
  witness. Tests the *circuit*.
- **Verification failure** — a proof exists but does not check against the claimed public signals.
  Tests the *verifier*, which is the thing an on-chain contract actually runs.

Only the second settles soundness against a malicious prover, since a cheater never runs the witness
generator at all. A suite with only the first would have looked complete and proved much less.

**Case 0 is a control: the honest witness must be ACCEPTED.** A circuit that rejects everything
passes a negative-test suite trivially. Without the control the other 52 results mean nothing.

### The case the brief demands: wrong `P_liq`

Displacing `pLiqHat` by δ grid steps from the canonical value, reference position:

| δ (grid steps of 1e-9) | 2\|R\|/tol | outcome |
|---|---|---|
| +1 | 2.647 | **REJECT** |
| −1 | 1.313 | **REJECT** |
| +2 | 4.627 | REJECT |
| −2 | 3.294 | REJECT |
| +10 | 20.47 | REJECT |
| +1e3 | 1.981e3 | REJECT |
| +1e6 | 1.980e6 | REJECT |
| +1e9 (= 1 whole unit of quote currency) | 1.980e9 | REJECT |
| +1e12 (= 1000 units) | 1.980e12 | REJECT |

Binary search for the widest displacement still accepted: **+0 up, −0 down.** On this position the
circuit pins `pLiqHat` to a single integer. A liquidation price wrong by 1e-9 quote currency does not
prove.

**Two distinct guards fire, one in each direction, and both are load-bearing:**

- δ > 0 → `line 100`, `within.out === 1` — the `LessEqThan` upper bound.
- δ < 0 → `line 95`, `Num2Bits(160)` on `shifted` — `2R + tol` goes negative, wraps to ≈ p, and
  blows the bit decomposition.

Neither alone would be sufficient. Removing either leaves the circuit open in exactly one direction,
and since the field has no order, the failure would be silent.

### Range discipline actually holds

All nine field-wrap attacks rejected, each at the specific `Num2Bits` guarding that input: `mHat =
p−1` (i.e. −1), `qHat`, `p0Hat`, `pLiqHat`, `mmrHat` as field negatives, and each input at exactly
2^80 / 2^60 / 2^30. Structural guards likewise: `s ∈ {0, 2, −2}` rejected, `q = 0` rejected, `mmr = 1`
and `mmr > 1` rejected.

### Verifier tests

Real proof, then tampered on the wire. All 8 public signals incremented one at a time → all 8
**REJECT**. Bent `pi_a`, bent `pi_c`, an all-identity-points "empty" proof, and a valid proof for a
*different* position replayed against these signals → all **REJECT**. A short-side (`s = −1`)
position proves and verifies against its own signals → ACCEPT.

### R1CS-level, bypassing the witness generator

`snarkjs wtns check` on the honest witness → ACCEPT. Witness vector entries 1–8 (the two outputs and
the six public inputs) incremented directly in the binary `.wtns` file → all 8 **REJECT**. The
constraint system, not merely the generator, binds those signals.

## 2026-07-27T10:18:22.179Z — The engine's float answer and the circuit's integer answer differ by up to 1.9e-4 quote currency — MEASURED

This is the number that decides whether the write-up is honest. Over 1600 scenarios
(both sides × 8 maintenance rates × 5 prices × 5 sizes × 4 leverages), comparing the engine's
IEEE-754 `P_liq` against the canonical integer `P_liq` recomputed from the scaled inputs:

| | |
|---|---|
| identical to the last 1e-9 digit | 1132 / 1600 (**70.8%**) |
| within one 1e-9 grid step | 1176 / 1600 (**73.5%**) |
| **max divergence** | **185,625 grid steps = 1.86e-4 quote currency** |
| worst case | `q=0.001, P0=250000, mmr=1/3, s=+1, lev=100` |

**Nearly 30% of scenarios do not agree to the last digit, and the tail is not small.** The divergence
is worst where the maintenance rate is not exactly representable at 1e-9 (`1/3`, `1/7`) and the

Consequence, and it must go in the paper: **a verified proof does not certify the number the engine
returned.** It certifies the number a fixed-point restatement returns. The two agree to the last
digit about 71% of the time in this envelope. Anyone writing "the proof shows the engine computed
correctly" is overclaiming by up to 1.9e-4 quote currency.

The mitigation, if the team wants the gap closed rather than merely disclosed, is for the service to
publish the *scaled integers* as the canonical request representation and have the engine work from
those — then the encoding gap is zero by construction. That is a service-side change and belongs to
the other session; this track only measured it.

## 2026-07-27T10:18:22.179Z — A fixed tolerance is the wrong shape; the correct bound scales with position size — MEASURED

First attempt used a constant `TOL = 1e21` (1e-6 quote currency), reasoned from "1e-9 precision".
Measured against 1000 realistic positions: **185 / 1000 exceeded it.** The reasoning was wrong and
only measurement caught it.

The residual is linear in position size, as measured:

| q | max abs residual |
|---|---|
| 0.001 | 6.666e-13 |
| 1 | 6.667e-10 |
| 37.5 | 2.500e-8 |
| 1000 | 6.667e-7 |
| 250000 | 1.667e-4 |

Because `R` is linear in `pLiqHat` with slope `qHat*(s*SCALE - mmrHat)`, rounding the price by at
most half a grid step moves `R` by at most `(1/2)*qHat*(SCALE + mmrHat)`. So the bound the circuit
enforces is

```
2*|R|  <=  qHat * (SCALE + mmrHat)
```

Re-measured over 1600 scenarios including maintenance rates that are *not* representable at 1e-9
(`1/3`, `1/7`, `0.0066666666666`):

- **violations: 0 / 1600**
- **tightest case: `2|R| / bound = 0.999997`**

The bound is tight, not slack — it is very nearly attained, so it is not hiding error behind
generous headroom. It is also derived from `qHat` and `mmrHat` *inside the circuit*, so a prover
cannot widen it without changing the position being proven about.
